# F24Y — Checked target descriptor backend (compile/link only)

Accepted parent: `a0bb68c225fb89bc11c82f6f8414fc9bccbdcc02`. Source basis: F24Y exact source evidence, 207 verified Git blobs, Arduino 3.3.12, SDK headers ESP-IDF 5.5.5. No physical permission.

- `DTNF24Y::Backend` implements the existing F24W owner contract with two private descriptors. It restricts paths to the existing F24O SOS/receipt grammar, checks parent directory and regular file status, treats only ENOENT as absent, and checks exact transfer lengths, seek, size, sync and close. No automatic retry or implicit I/O in destructors. Partial/ambiguous results are sticky faults. Append never uses O_TRUNC. Directory child/discovery is intentionally denied.
- `NativeVfs` uses actual POSIX descriptor calls on ESP/Linux; native Windows tests use corresponding CRT binary descriptor calls and `_commit`. Tests exercise the same backend and F24X port with disposable host files and an injected host mount. Neither host OS is FAT or actual ESP hardware.
- ESP target adapter contains checked SPI2 initialization (proposed same SD pins 35/37/36/47 and 1 MHz), no-format ESP-IDF SD-SPI mount at /sd, status-check enable, checked SDK unmount and checked SPI free. It assumes an independently qualified exclusive bus, power and media identity; none is established. SDK failure quarantines; no speculative cleanup or automatic remount. API return values do not prove underlying implementation behavior, actual CID continuity, or power-loss durability. The actual bus mapping/SDK transitive headers/linkage are target validation gates.
- New profile inherits all F24X deny flags. It retains a constant link-anchor table of member-function pointers in the ELF; no application caller, no target instance, no grant, no serial command, no runtime mount. The live logger and F24X port are unchanged and permanently denied. The link-only table verifies compiled methods and SDK linkage, not execution. Normal scheduled LoRa and existing power/pin/SPI setup remain inherited if flashed; this is NOT a hardware/RF-silent image. Do not upload.
