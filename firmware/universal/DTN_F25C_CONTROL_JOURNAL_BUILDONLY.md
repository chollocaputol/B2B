# F25C / A-06 — Type-aware SOS and CANCEL journal, build-only

Accepted parent: `38a5e289b9585e932b10bcd1cdd8472a4c94ea23`, tree `2105cd781148a99c6eb58330e0ceca30dc9c1af9`. Profile `tbeam-supreme-f25c-control-journal-deny-build-only` extends F25B. Target permission is permanently denied; do not flash. Inherited operational transmissions remain enabled if flashed; this is not RF-silent firmware. No physical SD, relay activation, cloud changes, or push.

- Capture only fresh locally constructed CANCEL after the existing NVS intent gate (where enabled), and newly accepted peer cancellation after the existing payload and peer-state checks. No reconstructed reboot retry, duplicate ACK, telemetry, orphan/mismatched CANCEL or rejected packet capture. No change to on-air protocol (62 bytes), peer-state admission, or radio retry/ACK logic. Capture is best-effort into the same eight-entry RAM queue; full queue can drop CANCEL. No radio control is delayed waiting for storage and no durability is implied.
- Journal identity is `(origin, event, packet type)`. Byte-identical same-type duplicates are coalesced in queue/replay, differing bytes conflict; SOS and CANCEL for the same event are distinct. Same existing F24Z service, F25B lifecycle, F24W owner and F25A task guard; no second queue or alternate filesystem owner.
- Existing 88-byte `F24M` v1 SOS frames and 40-byte `F24N` v1 SOS receipts retain their exact encoding. F25C adds canonical version 2 CANCEL frames/receipts (header byte 4 = 2; reserved byte 6 becomes type 4; other reserved bytes stay zero). Frame length, CRC positions, filenames and session bounds unchanged. Decoder cross-checks version, type, packet identity and CANCEL message event/origin. Earlier readers reject v2, not silently skip; do not downgrade mixed journals. F25C reads v1 SOS plus v2 CANCEL. No historical journal rewrite or card migration.
- Typed ledger chooses SOS first when both records are pending, regardless of enumeration order. A record-set projection marks CancelSeen as terminal for that origin/event while cancellation remains in the bounded ledger, even if SOS appears later. This is a host-tested record-set rule, not an actual shore state machine or live distress override. Late SOS still needs delivery as historical evidence; a future shore consumer must preserve cancellation dominance across durable transactions, restarts, and arbitrary arrival order. No actual replay transport or production shore receipt provider is added. The service's current runtime remains deny-only and only exercises append admission.
- Receipts bind type, origin, event and packet CRC, and require an independent verifier supplied with exact packet bytes. CRC is not cryptographic identity/authentication. Synthetic verifier tests compare exact bytes and receipt identity; no authenticated real receipt exists. Neighbor ACKs never confer final delivery. Post-write verifier failure latches writer fault in F25C; uncertain writes never retried automatically. F25B witness/closure restrictions and bounds retained. No physical positive path or crash durability claim.
- The F24X source assertion previously forbade the literal CANCEL anywhere in the header; it now checks the default SOS-only gate and opt-in F25C branch. Its other assertions are preserved; historical accepted reports are not rewritten. Legacy-mode host tests also check rejection of valid CANCEL frames, and identical SOS encoding.

Host validation uses fresh private disposable directories; no real card or external writers. Target runtime, loss under full RAM queue, external writer/symlink resistance, authenticated closure/receipt providers, rotation, actual shore monotonic projection, storage durability and latency still require separate work. Candidate has not run on Windows or ESP32 until the guarded test report is returned.
