# F24Z: owner-bound session discovery and serialized SOS service (build only)

Parent: e2cd3526e9d0d216b8294a600613cad0836fa06e. DTN only; no flash, physical SD, relay, cloud or push. The live logger is unchanged and permanently denied. This profile inherits ordinary scheduled RF if flashed; it is NOT a globally RF-silent image.

The same F24W MountOwner and F24Y descriptor backend now perform a checked bounded read-only directory snapshot. It requires the exact vessel root and current session directory, rejects unknown directories, ambiguous entries, duplicate or excessive sessions, I/O and close errors. It copies at most 12 old names, sorts lexically (not chronology), and requires EOF within 64 reads. No directory handle escapes. Loss of authority mid-operation quarantines state, with no blind close or unmount. Session closure is supplied by an independent witness, not established by directory names. Host tests use trusted disposable roots, not adversarial path aliases or physical media.

F24Z Service owns one owner, existing F24X port, F24M writer, F24N replay and receipt writer. It consumes an externally supplied existing queue and acknowledges only after the checked append. A nonblocking atomic transaction gate protects these service operations against overlap; no interrupt-disabling I/O lock. Radio/export/history busy and old-session urgency at admission defer rather than fault, provided actual ownership evidence remains valid. Mid-operation scheduling changes can still fail closed. Caller must synchronize queue and witness and provide stable grants throughout operations. No actual RTOS task, radio arbitration, physical card identity, mount grant or global interposition is implemented. The current session must already exist; no directory creation/migration of telemetry or other clients. The summary is a copied old-session ledger summary, not a physical delivery or current queue inventory. Mock shore receipts are test-only; actual authentication remains pending. CANCEL is not supported.

The target compilation profile retains the direct checked directory method and composed service methods via a data link anchor, using permanent deny witnesses for the service. No runtime caller, no global service instance and no second active SD driver. Link success is not execution proof; compiler optimization may remove denied branches. Positive host tests on real host files use simulated mount/identity and injected directory errors. Windows SDK and target build pending. No new permission or disposable SD authorization.
