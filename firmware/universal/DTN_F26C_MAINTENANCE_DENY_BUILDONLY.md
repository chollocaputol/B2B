No new physical authorization. Do not flash. The operational runtime remains immutable deny. Normal radio transmissions are inherited, not RF silence.

## Bounded queue bypass

A blocked new event must not stop an already queued counterpart of a persisted event from using its reserved ledger slot. Only after the normal FIFO head is capacity-blocked, scan the remaining at most seven entries. Coalesce exact persisted duplicates, or append an eligible counterpart, verify checked write/readback, insert in the existing ledger and consume that exact selected queue item. Preserve order of all other items. No unrelated new event bypasses; malformed/conflicting candidates fault. No extra queue, packet format or ledger capacity. The caller must serialize queue access as before. A full queue can still reject an incoming CANCEL; an exhausted physical journal or ledger still blocks; no storage fault retry or durable claim.

## Read-only maintenance extraction (host only)

The strict service's new host-only `startMaintenance(vessel,reservedAbsentPath)` requires a distinct independent maintenance witness (absent method denies), a valid independent mount identity and a stable complete closed-session count <=12. No active directory is created; the existing discovery backend requires the reserved logical path to be absent, rather than excluding an actual session. The same owner, checked backend and port are used; no write handle, packet append, receipt append or replay is admitted in this mode. The backend checks closed claims and bounds on every I/O. The path is not exposed as a general reader. Host calls `discover`, `archiveCount`, `archiveSession(index, metadata)` and `archiveFrame(index,isReceipt,frameIndex,copy)`. Session metadata binds the path and closure evidence and checks actual journal presence/length. Frame reads use exact length/offset and decode CRC/type before returning a copy; zero-byte claims require absence. All outputs clear on rejection/fault. No callbacks or descriptors escape. Each result describes only the current verified read, not completeness of an external archive. Unknown regular files are not part of this journal-specific extraction. Empty inventory, all 12 sessions, and >32 unique records are supported without normal replay or another ledger. The caller must read all sessions/frames and retain exact bytes; no external archive authority or authenticated receipt verifier supplied. Host maintenance APIs are excluded when ARDUINO or ESP_PLATFORM is defined. Read-only here describes the journal operations, not a qualified physical read-only filesystem mount.

## Remaining A08-02b work

This is not a durable archive checkpoint, session rotation or reclamation implementation. No journal removal, rename, truncation, retired-history index, automatic migration, or source-of-truth change. Before retirement, establish independently authenticated receipt coverage for exact bytes (including cross-session relationships), a complete durable archive manifest with media/session identity and anti-rollback authority, durable retained duplicate/cancellation identity, interrupted checkpoint recovery, and a separate controlled removal/rotation contract. A received receipt frame has only passed format/integrity checks, not authentication. A valid but unpaired record is not eligible to retire. Full inventory extraction can provide bytes to a later archive verifier, but does not itself mark any record delivered. Existing closure evidence uses synthetic witnesses on private host fixtures; same-length substitutions and mid-call external mutation are outside this test's qualified trust model. No physical SPI/SD, hardware, shore network, cloud, or runtime timing validation.
